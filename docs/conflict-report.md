# Конфликт и отмена

## Исходная точка и две ветки

Исходная точка — ветка `lab-base`, созданная от `main` с начальным `config.txt`:

```
support_hours=09:00-17:00
response_minutes=60
```

От `lab-base` созданы две независимые ветки:

- `docs/early` (карточка EARLY): начало работы 08:30, конец остаётся 17:00. Итоговая строка: `support_hours=08:30-17:00`. Коммит: `Start support at 08:30`, SHA `<SHA_EARLY>`.
- `docs/late` (карточка LATE): конец работы 18:00, начало остаётся 09:00. Итоговая строка: `support_hours=09:00-18:00`. Коммит: `End support at 18:00`, SHA `<SHA_LATE>`.

Общий предок обеих веток — `lab-base`, SHA `<SHA_LAB_BASE>`. Каждая ветка изменила одну и ту же строку, но не знала об изменении другой.

## Текст конфликта и смысл каждой стороны

Первым был слит PR `docs/early`, поэтому `main` получила 08:30-17:00. При разрешении конфликта PR `docs/late` в `config.txt` появился блок:

```
<<<<<<< docs/late
support_hours=09:00-18:00
=======
support_hours=08:30-17:00
>>>>>>> main
```

- Верхняя часть (текущая ветка, `HEAD`) — `docs/late`: сохраняет начало 09:00 и переносит конец на 18:00 (запрос LATE).
- Нижняя часть (входящая сторона, `main`) — уже принятый EARLY: переносит начало на 08:30 и оставляет конец 17:00.

Git не может выбрать итог сам: обе стороны изменили одну строку по-разному, поэтому нужно решение человека.

## Итоговое значение и обоснование

Выбрано значение `support_hours=08:30-18:00`, `response_minutes=60` не менялся.

Обоснование: по `CARDS.md` оба запроса действуют одновременно. EARLY требует начало в 08:30, LATE требует конец в 18:00. Ни одна из сторон по отдельности не выполняет оба требования, поэтому берётся начало из EARLY и конец из LATE. Все маркеры конфликта удалены, в файле осталась ровно одна строка `support_hours`.

## Команда и результат проверки

Команда проверки: `python check_config.py --combined`

Результат: `PASS: конфигурация соответствует выбранной проверке`.

Проверка проходит, потому что в файле нет маркеров конфликта, `response_minutes=60` положительный, окончание позже начала, а интервал равен `08:30-18:00`. Если запускать проверку без доступа к терминалу, результат подтверждён вручную по содержимому `config.txt` в `main`.

## SHA ошибочного коммита и SHA revert

- Ошибочный коммит: `Set invalid response time for lab`, SHA `<BAD_SHA>`. Он изменил только `response_minutes` с 60 на 0. Проверка `check_config.py` на нём падала с `FAIL`.
- Отменяющий коммит (`revert`): SHA `<REVERT_SHA>`. Он создан командой `git revert` или кнопкой Revert в GitHub, вернул `response_minutes=60` и сохранил объединённое расписание 08:30-18:00.

Оба коммита остаются в истории `main`: ошибка не стёрта, а отменена новым коммитом.
